## 1. 产品定位与目标

### 1.1 一句话定位

**拾序待办**是一款 **本地优先、键盘流优先、多视图** 的 PC 端个人待办管理软件，帮助用户在 3 秒内记下一件事，在 10 秒内看清今天要做什么。

### 1.2 设计原则

| 原则 | 说明 | 反面案例 |
|---|---|---|
| 本地优先 | 数据先写本地，离线可用，可导出 | 强制登录才能使用 |
| 键盘流 | 高频操作全部有快捷键 | 只能鼠标点击 |
| 捕捉成本最低 | 全局快捷键一键呼出，回车即存 | 打开软件 → 新建 → 选清单 → 输入 |
| 多视图一致 | 同一份数据，卡片 / 看板 / 时间线三种视角 | 不同视图数据割裂 |
| 克制的功能 | 不做团队协作、不做社交、不做花哨动效 | 首页塞满统计图表 |
| 数据可迁移 | 一键导出 JSON / Markdown | 数据锁死在云端 |

### 1.3 与竞品差异

| 竞品 | 拾序待办的差异 |
|---|---|
| Todoist | 本地优先、无强制登录、多视图自带看板 |
| TickTick | 键盘流更彻底、视觉更克制 |
| Things 3 | 跨平台（Windows/Linux 也能用）、开源可扩展 |
| Microsoft To Do | 多视图、子待办进度、项目/标签双维度 |
| Notion | 启动快、专注待办、不上重型数据库 |

### 1.4 成功指标（MVP 阶段）

- 从呼出到保存一条待办：**≤ 3 秒**
- 冷启动到可用：**≤ 1.5 秒**
- 10000 条待办下滚动帧率：**≥ 55 fps**
- 数据丢失率：**0**（本地 SQLite + 每日自动备份）

## 2. 用户与场景

### 2.1 目标用户

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| 职场个人用户 | 25–40 岁，知识工作者 | 快速记录、按项目/标签分类、看板管理 |
| 独立开发者 / 设计师 | 追求效率工具，喜欢键盘流 | 全局快捷键、命令面板、多视图 |
| 学生 / 研究者 | 任务多、时间紧 | 时间线视图、截止日期提醒 |
| 隐私敏感用户 | 不愿把数据放云端 | 本地存储、可导出、无账号 |

### 2.2 典型场景

**场景 A：会议中快速记录**
- 用户在开会，突然被分配一件事
- 按 `Ctrl+Shift+Space` 呼出输入框
- 输入 `明天 18:00 提交周报 #工作`，回车
- 3 秒完成，不打断会议

**场景 B：早晨规划一天**
- 打开软件，切到「今天」视图
- 看到逾期任务用红色标记
- 把不重要的拖到「即将到来」
- 切到看板视图，把「待办」拖到「进行中」

**场景 C：周末回顾**
- 切到「已完成」，看本周完成了什么
- 切到「归档」，清理旧任务
- 导出 Markdown 备份

### 4.2 导航结构

| 一级导航 | 含义 | 数据过滤规则 |
|---|---|---|
| 收集箱 | 未分类、无日期的待办 | `due IS NULL AND status != 'done' AND archived = 0` |
| 今天 | 今天到期 + 已逾期未完成 | `due < 明天0点 AND status != 'done'` |
| 即将到来 | 明天起未来 7 天 | `due >= 明天0点 AND due < 7天后 AND status != 'done'` |
| 全部待办 | 所有未完成 | `status != 'done' AND archived = 0` |
| 已完成 | 已完成 | `status = 'done' AND archived = 0` |
| 归档 | 已归档 | `archived = 1` |
| 标签 | 按标签过滤 | `tags CONTAINS value` |
| 项目 | 按项目过滤 | `project = value` |

### 4.3 视图切换

| 视图 | 用途 | 数据分组 |
|---|---|---|
| 卡片流 | 日常浏览、勾选、快速扫视 | 按优先级 + 截止日期排序 |
| 看板 | 状态管理、拖拽推进 | 按 status 分三列 |
| 时间线 | 日程规划、看清节奏 | 按 due 分组（逾期/今天/明天/周X/日期/无日期） |

## 5. 核心交互设计

### 5.1 快速添加（最高频入口）

**触发方式：**
- 全局快捷键 `Ctrl+Shift+Space`（系统级，Tauri 注册）
- 点击侧边栏「添加待办」按钮
- 点击主视图右上角 `+`

**输入解析规则：**

| 语法 | 示例 | 解析结果 |
|---|---|---|
| `#标签` | `#工作` | tags: ['工作'] |
| `@项目` | `@灵感工具` | project: '灵感工具' |
| `今天` | `今天 提交周报` | due: 今天 18:00 |
| `明天` | `明天 开会` | due: 明天 09:00 |
| `后天` | `后天 体检` | due: 后天 09:00 |
| `下周` | `下周 复盘` | due: 7 天后 09:00 |
| `HH:MM` | `18:30 下班` | 覆盖默认时间；若已过则推到明天 |
| 组合 | `明天 18:00 和张总开会 #工作 @项目A` | 全部解析 |

**交互细节：**
- 输入框 `contenteditable`，支持粘贴多行
- 回车保存，`Shift+回车` 换行
- `Esc` 关闭，不保存
- 保存后 Toast 提示解析结果（日期/项目/标签）
- 底部显示 AI 建议标签（基于历史高频标签）

### 5.2 任务操作

| 操作 | 入口 | 反馈 |
|---|---|---|
| 完成 | 卡片勾选框 / 详情「标记完成」 | 勾选动效 + 删除线 + Toast |
| 取消完成 | 同上 | 恢复原状 |
| 改状态 | 详情状态选择器 / 看板拖拽 | 即时更新 + Toast |
| 改优先级 | 详情优先级选择器 | 即时更新 + Toast |
| 改日期 | 详情日期输入 + 快捷按钮 | 即时更新 + Toast |
| 加标签 | 详情标签编辑器 | 输入回车确认 |
| 加子待办 | 详情子待办区 | prompt 输入 |
| 归档 | 详情「归档」 | 从主列表移除 |
| 删除 | 详情垃圾桶图标 | confirm 确认 |

### 5.3 看板拖拽

**拖拽流程：**
```
dragstart → 卡片半透明，设置 dataTransfer
dragover  → 目标列高亮（drag-over 类）
drop      → 读取任务 ID，更新 status，重渲染，Toast
dragend   → 清除所有拖拽态
```

**状态变更副作用：**
- 拖到「已完成」→ 设置 `completedAt = now()`
- 从「已完成」拖出 → 清空 `completedAt`
- 触发侧边栏计数更新

### 5.4 键盘快捷键

| 快捷键 | 作用 | 作用域 |
|---|---|---|
| `Ctrl+Shift+Space` | 快速添加 | 全局（系统级） |
| `Ctrl+K` | 命令面板 | 应用内 |
| `Ctrl+P` | 聚焦搜索 | 应用内 |
| `Esc` | 关闭浮层 / 失焦 | 应用内 |
| `Enter` | 快速添加保存 | 浮层内 |
| `Shift+Enter` | 换行 | 浮层内 |
| `J` / `K` | 上下选择任务 | 列表（P1） |
| `Enter` | 编辑选中任务 | 列表（P1） |
| `X` | 完成选中任务 | 列表（P1） |
| `1/2/3` | 切视图 | 应用内（P1） |

### 5.5 搜索与过滤

- 搜索范围：标题、描述、标签、项目
- 实时过滤（`input` 事件，带 100ms 防抖）
- 结果高亮关键词（`<mark>`）
- 优先级 chips：全部 / 高 / 中 / 低
- 搜索状态下保持视图切换能力

## 7. 数据模型

### 7.1 SQLite Schema

```sql
-- 任务表
CREATE TABLE tasks (
  id            TEXT PRIMARY KEY,           -- UUID v4
  title         TEXT NOT NULL,
  description   TEXT DEFAULT '',
  status        TEXT NOT NULL DEFAULT 'todo',   -- todo | doing | done
  priority      TEXT NOT NULL DEFAULT 'none',   -- high | medium | low | none
  due_at        INTEGER,                    -- UTC 毫秒时间戳，可空
  project_id    TEXT,                       -- 外键 projects.id
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  completed_at  INTEGER,
  archived      INTEGER NOT NULL DEFAULT 0,
  "order"       REAL NOT NULL DEFAULT 0,    -- fractional index，用于手动排序
  FOREIGN KEY (project_id) REFERENCES projects(id)
);

CREATE INDEX idx_tasks_status    ON tasks(status);
CREATE INDEX idx_tasks_due       ON tasks(due_at);
CREATE INDEX idx_tasks_project   ON tasks(project_id);
CREATE INDEX idx_tasks_archived  ON tasks(archived);
CREATE INDEX idx_tasks_updated   ON tasks(updated_at);

-- 子待办表
CREATE TABLE subtasks (
  id         TEXT PRIMARY KEY,
  task_id    TEXT NOT NULL,
  text       TEXT NOT NULL,
  done       INTEGER NOT NULL DEFAULT 0,
  "order"    REAL NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE
);

CREATE INDEX idx_subtasks_task ON subtasks(task_id);

-- 标签表
CREATE TABLE tags (
  id    TEXT PRIMARY KEY,
  name  TEXT NOT NULL UNIQUE,
  color TEXT NOT NULL DEFAULT '#5b5bd6'
);

-- 任务-标签关联
CREATE TABLE task_tags (
  task_id TEXT NOT NULL,
  tag_id  TEXT NOT NULL,
  PRIMARY KEY (task_id, tag_id),
  FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE,
  FOREIGN KEY (tag_id)  REFERENCES tags(id)  ON DELETE CASCADE
);

-- 项目表
CREATE TABLE projects (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL UNIQUE,
  color      TEXT NOT NULL DEFAULT '#5b5bd6',
  created_at INTEGER NOT NULL
);

-- 提醒表（P1）
CREATE TABLE reminders (
  id         TEXT PRIMARY KEY,
  task_id    TEXT NOT NULL,
  remind_at  INTEGER NOT NULL,
  fired      INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE
);

-- 设置表
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 操作日志（用于 P2 同步和撤销）
CREATE TABLE op_log (
  id         TEXT PRIMARY KEY,
  op_type    TEXT NOT NULL,       -- create | update | delete
  entity     TEXT NOT NULL,       -- task | subtask | tag | project
  entity_id  TEXT NOT NULL,
  payload    TEXT NOT NULL,       -- JSON
  created_at INTEGER NOT NULL
);
```

### 7.2 TypeScript 类型

```typescript
export type TaskStatus = 'todo' | 'doing' | 'done';
export type TaskPriority = 'high' | 'medium' | 'low' | 'none';

export interface Task {
  id: string;
  title: string;
  description: string;
  status: TaskStatus;
  priority: TaskPriority;
  dueAt: number | null;
  projectId: string | null;
  tags: Tag[];
  subtasks: Subtask[];
  createdAt: number;
  updatedAt: number;
  completedAt: number | null;
  archived: boolean;
  order: number;
}

export interface Subtask {
  id: string;
  taskId: string;
  text: string;
  done: boolean;
  order: number;
  createdAt: number;
}

export interface Tag {
  id: string;
  name: string;
  color: string;
}

export interface Project {
  id: string;
  name: string;
  color: string;
  createdAt: number;
}

export interface Filter {
  type: 'inbox' | 'today' | 'upcoming' | 'all'
      | 'completed' | 'archive' | 'tag' | 'project';
  value: string | null;
}

export interface AppState {
  tasks: Task[];
  tags: Tag[];
  projects: Project[];
  filter: Filter;
  search: string;
  priorityFilter: 'all' | TaskPriority;
  view: 'card' | 'board' | 'timeline';
  selectedId: string | null;
}
```

### 7.3 数据一致性规则

| 规则 | 说明 |
|---|---|
| 时间统一 | 存储 UTC 毫秒，展示按本地时区 |
| 软删除 | MVP 用硬删除 + 每日备份；P1 引入 `deleted_at` |
| ID 生成 | UUID v4，客户端生成，便于未来同步 |
| 完成态 | `status = 'done'` 时自动写 `completed_at` |
| 归档 | `archived = 1` 的任务不出现在非归档视图 |
| 排序 | 手动排序用 fractional index，避免全表重排 |

### 8.4 Pinia Store 设计

```typescript
// stores/task.ts
export const useTaskStore = defineStore('task', {
  state: () => ({
    tasks: [] as Task[],
    loading: false,
    selectedId: null as string | null,
  }),

  getters: {
    selected: (s) => s.tasks.find(t => t.id === s.selectedId) || null,

    filtered: (s) => (filter: Filter, search: string,
                      priority: string) => {
      // 纯函数，复用原型中的过滤逻辑
    },

    counts: (s) => ({
      inbox: s.tasks.filter(t =>
        !t.dueAt && t.status !== 'done' && !t.archived).length,
      today: s.tasks.filter(t =>
        t.dueAt && t.dueAt < tomorrowStart() &&
        t.status !== 'done' && !t.archived).length,
      // ...
    }),
  },

  actions: {
    async load() {
      this.loading = true;
      this.tasks = await taskApi.list();
      this.loading = false;
    },

    async create(input: CreateTaskInput) {
      const task = await taskApi.create(input);
      this.tasks.unshift(task);
      this.selectedId = task.id;
      return task;
    },

    async update(id: string, patch: UpdateTaskInput) {
      const task = await taskApi.update(id, patch);
      const idx = this.tasks.findIndex(t => t.id === id);
      if (idx >= 0) this.tasks[idx] = task;
    },

    async toggleDone(id: string) {
      const task = await taskApi.toggleDone(id);
      const idx = this.tasks.findIndex(t => t.id === id);
      if (idx >= 0) this.tasks[idx] = task;
    },

    async delete(id: string) {
      await taskApi.delete(id);
      this.tasks = this.tasks.filter(t => t.id !== id);
      if (this.selectedId === id) this.selectedId = null;
    },
  },
});
```

## 10. 性能与可靠性

### 10.1 性能优化

| 问题 | 方案 |
|---|---|
| 大量任务渲染慢 | 虚拟滚动（`vue-virtual-scroller`），阈值 200 条 |
| 频繁重渲染 | Pinia `computed` 缓存过滤结果 |
| 搜索卡顿 | 100ms 防抖 + `computed` |
| SQLite 频繁写 | 批量写 + WAL 模式 + 事务 |
| 冷启动慢 | Rust 侧异步初始化 DB，前端先渲染骨架屏 |
| 看板拖拽掉帧 | 使用 CSS transform，避免 layout thrashing |
| 日期格式化耗时 | 预生成 formatter，缓存常用格式 |

### 10.2 可靠性

| 风险 | 缓解 |
|---|---|
| 数据丢失 | 每日自动备份到 `~/.shixu/backups/`，保留 7 天 |
| DB 损坏 | WAL 模式 + 启动时 `PRAGMA integrity_check` |
| 崩溃恢复 | 操作写 op_log，启动时检查未完成事务 |
| 时间错误 | 存储 UTC，展示本地，跨时区不丢数据 |
| 提醒未触发 | 启动时扫描未触发提醒，补发 |
| 导出失败 | 导出前先写临时文件，成功后原子重命名 |

### 10.3 可访问性

- 所有交互元素支持 Tab 键聚焦
- 焦点态有明显的 `:focus-visible` 样式
- 颜色对比度 ≥ 4.5:1（正文）
- 图标按钮带 `title` 或 `aria-label`
- 支持系统字体缩放
