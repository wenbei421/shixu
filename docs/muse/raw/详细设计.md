# Muse 灵感库 PC 端 · 功能详细设计

---

## 1. 文档说明

### 1.1 目的
定义 Muse 灵感库 PC 端**功能边界、交互流程、数据结构、异常规则与验收标准**，作为开发、测试、验收的统一依据。

### 1.2 范围
- 覆盖：捕捉、整理、标签、项目、搜索、视图、回顾、归档、设置、导入导出、本地存储。
- 暂不覆盖：多端同步、团队协作、插件市场（列入 P2）。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 灵感（Note） | 一条最小记录单元，含正文、标签、项目、状态 |
| 收件箱（Inbox） | 未整理灵感的默认落点，等价于 `status = 'new'` |
| 整理 | 为灵感补全标签、项目、状态的动作 |
| 输出 | 灵感被转化为文章、任务、产品的结果 |
| 回顾（Review） | 按时间或随机策略重新浏览灵感 |
| 归档 | 不删除但移出主视图 |

### 1.4 参考
- 原型：`muse_prototype.html`
- 数据库：`muse_schema.sql` / `muse_seed.sql`
- 表前缀 `muse_`，视图前缀 `v_muse_`，主键雪花算法

### 4.3 灵感状态机

```
        ┌─────────────────────────────────────┐
        │                                     │
        ▼                                     │
     [new] ──验证──> [check] ──推进──> [doing] ──输出──> [done]
        │              │               │              │
        │              │               │              │
        └──────────────┴───────────────┴──────────────┘
                          │
                          ▼
                      [archived]
                          │
                          ▼
                      [deleted]
```

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `new` | 新想法，未整理 | 打标签、选项目、改状态、归档、删除 |
| `check` | 待验证 | 同上 |
| `doing` | 进行中 | 同上 + 转任务 |
| `done` | 已输出 | 归档、删除、作为关联素材 |
| `archived` | 归档 | 取消归档、删除 |
| `deleted` | 软删除 | 恢复、彻底删除 |

### 4.4 数据流

```
用户输入
   │
   ▼
前端 Store（Zustand）
   │  invoke
   ▼
Tauri Command（Rust）
   │  rusqlite / sqlx
   ▼
SQLite（muse.db）
   │  触发器
   ▼
FTS5 / 视图
```

### 4.5 通知与反馈

| 类型 | 场景 | 形式 | 时长 |
|---|---|---|---|
| Toast | 保存成功、状态切换、归档 | 底部居中深色条 | 1.8s |
| 内联提示 | 输入为空、搜索无结果 | 列表空状态 | 常驻 |
| 确认框 | 删除、清空回收站 | 模态 | 手动 |
| 错误条 | 数据库异常、写入失败 | 顶部红色条 | 5s |

### FR-01 快速捕捉

| 项 | 内容 |
|---|---|
| 编号 | FR-01 |
| 优先级 | P0 |
| 目标 | 让记录成本趋近于 0，不打断当前工作 |

#### 5.1.1 入口
- 全局快捷键 `Ctrl + Shift + Space`
- 左栏「捕捉灵感」按钮
- 托盘图标菜单「新建灵感」
- 剪贴板监听（可选，P1）

#### 5.1.2 界面元素

| 元素 | 说明 |
|---|---|
| 输入区 | contenteditable，支持多行 |
| 占位符 | “记下此刻的想法… 支持 #标签 @项目” |
| AI 建议标签 | 展示历史高频标签，点击即选中 |
| 工具按钮 | `#`、`@`、图片、链接、语音 |
| 保存按钮 | 内容非空才可点 |
| 提示 | “Esc 关闭 / Enter 保存” |

#### 5.1.3 交互流程

```
1. 用户按下快捷键
2. 浮层淡入，输入框自动聚焦
3. 用户输入内容
   ├─ 输入 #xxx → 解析为标签
   ├─ 输入 @xxx → 解析为项目
   └─ 点击建议标签 → 加入已选标签
4. 按 Enter 或点击保存
5. 校验内容非空
6. 生成雪花 ID，写入 muse_notes
7. 绑定标签（muse_note_tags）
8. 关闭浮层，Toast 提示
9. 若当前视图能显示，刷新列表并选中新条目
```

#### 5.1.4 解析规则

| 语法 | 正则 | 处理 |
|---|---|---|
| 标签 | `#([^\s#@]+)` | 去重后写入 `muse_tags` + `muse_note_tags` |
| 项目 | `@([^\s#@]+)` | 匹配已有项目名；不存在则自动创建 |
| 正文 | 去除上述语法后 trim | 写入 `muse_notes.content` |

#### 5.1.5 数据操作

```sql
-- 事务
BEGIN;
INSERT INTO muse_notes(id, content, status, source, created_at, updated_at)
VALUES (?, ?, 'new', 'quick', ?, ?);

INSERT INTO muse_note_tags(note_id, tag_id, created_at)
SELECT ?, id, ? FROM muse_tags WHERE name = ?;
COMMIT;
```

#### 5.1.6 业务规则

| 规则 | 说明 |
|---|---|
| BR-01-01 | 内容为空不允许保存 |
| BR-01-02 | 正文长度上限 10000 字符 |
| BR-01-03 | 单条灵感最多 20 个标签 |
| BR-01-04 | 项目名不存在时自动创建 |
| BR-01-05 | 保存后状态固定为 `new` |

#### 5.1.7 异常处理

| 异常 | 处理 |
|---|---|
| 内容为空 | 保存按钮置灰 |
| 数据库写入失败 | 保留输入，提示重试 |
| 快捷键冲突 | 设置中可修改 |
| 输入超长 | 截断并提示 |

#### 5.1.8 验收标准

- [ ] 冷启动到浮层可输入 ≤ 300ms
- [ ] 保存到写入完成 ≤ 100ms
- [ ] 连续捕捉 10 条无卡顿
- [ ] 标签、项目解析正确率 100%
- [ ] Esc 关闭后内容不残留
