# 基于 Tauri + Vue 3 的 DeepSeek 网页任务执行方案

你的实际场景不是传统聊天，而是：

1. 用户在 Vue 页面输入一段提示词；
2. Tauri 打开 DeepSeek 网页版；
3. 将这段提示词自动填入 DeepSeek；
4. 自动执行；
5. 等待 DeepSeek 生成完成；
6. 提取最终结果；
7. 将结果返回给 Vue 页面或保存到本地。

完整链路：

```text
Vue 3 输入提示词
        ↓
Tauri Rust Command
        ↓
DeepSeek WebView
        ↓
自动填入提示词并执行
        ↓
轮询网页 DOM
        ↓
判断生成完成
        ↓
提取最终结果
        ↓
Rust 返回 Vue
```

本方案：

- 不使用 Node.js；
- 不使用 Playwright；
- 不使用 Chrome CDP；
- 不使用 DeepSeek API Key；
- 使用 Tauri 自带的系统 WebView；
- 使用 Rust 控制任务流程；
- 使用 JavaScript 操作 DeepSeek 网页 DOM。

需要说明：

> Tauri 本身没有独立的浏览器内核。  
> Windows 使用 WebView2，macOS 使用 WKWebView，Linux 通常使用 WebKitGTK。

## 一、基于当前仓库的调整方向

当前仓库：

```text
ai-fzx/deepseek-skills
```

原项目核心逻辑位于：

```text
scripts/chat.js
scripts/ensure_chrome.js
```

原方案是：

```text
Node.js
  ↓
Playwright
  ↓
Chrome CDP
  ↓
DeepSeek 网页
```

需要改造成：

```text
Tauri Rust
  ↓
Tauri WebView
  ↓
DeepSeek 网页
```

原来 `chat.js` 中的逻辑可以迁移到 Rust：

| 原 Node.js 逻辑 | 新 Tauri/Rust 逻辑 |
|---|---|
| `chromium.connectOverCDP()` | Tauri 创建 DeepSeek WebView |
| `page.goto()` | WebView 加载远程 URL |
| `locator()` | 注入 JavaScript 查询 DOM |
| `input.fill()` | JavaScript 设置输入框内容 |
| `keyboard.press('Enter')` | JavaScript 派发键盘事件 |
| `extractLastReply()` | JavaScript 提取结果 |
| `waitForReplyDone()` | Rust 定时轮询网页状态 |
| JSON stdout | Tauri Command 返回结构体 |
| Chrome 登录状态 | Tauri WebView Cookie 持久化 |

# 三、任务模型设计

因为你的场景是“一次提示词对应一次网页任务”，建议不要将它设计成聊天消息，而是设计成任务。

## 任务流程

```text
IDLE
  ↓
PREPARING
  ↓
CHECKING_LOGIN
  ↓
SUBMITTING
  ↓
RUNNING
  ↓
EXTRACTING
  ↓
COMPLETED
```

异常流程：

```text
任意状态
  ↓
FAILED
```

## Rust 数据结构

```rust name=src-tauri/src/models.rs
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ExecuteTaskRequest {
    pub prompt: String,

    /// 是否执行前新建 DeepSeek 对话
    #[serde(default = "default_true")]
    pub new_chat: bool,

    /// 最大等待时间，单位毫秒
    #[serde(default = "default_timeout")]
    pub timeout_ms: u64,
}

fn default_true() -> bool {
    true
}

fn default_timeout() -> u64 {
    180_000
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ExecuteTaskResponse {
    pub success: bool,

    pub prompt: String,

    pub result: Option<String>,

    pub error: Option<String>,

    pub message: Option<String>,

    pub elapsed_ms: u64,

    pub status: TaskStatus,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "SCREAMING_SNAKE_CASE")]
pub enum TaskStatus {
    Idle,
    Preparing,
    CheckingLogin,
    Submitting,
    Running,
    Extracting,
    Completed,
    Failed,
}
```

# 四、DeepSeek WebView 设计

建议创建一个单独的 DeepSeek WebView 窗口：

```text
主窗口：
deepseek-task-app

DeepSeek 窗口：
deepseek-web
```

开发阶段建议显示 DeepSeek 窗口，因为用户需要：

- 首次登录；
- 处理验证码；
- 查看网页是否加载成功；
- 处理登录失效；
- 调试页面结构变化。

生产环境可以增加“后台运行”模式，但不建议一开始就隐藏。

## 创建 DeepSeek 窗口

```rust name=src-tauri/src/deepseek.rs
use tauri::{AppHandle, Manager, WebviewUrl, WebviewWindowBuilder};

const DEEPSEEK_URL: &str = "https://chat.deepseek.com/";

pub fn ensure_window(app: &AppHandle) -> Result<(), String> {
    if let Some(window) = app.get_webview_window("deepseek-web") {
        window
            .show()
            .map_err(|e| format!("显示 DeepSeek 窗口失败: {e}"))?;

        return Ok(());
    }

    let url = DEEPSEEK_URL
        .parse()
        .map_err(|e| format!("DeepSeek URL 解析失败: {e}"))?;

    WebviewWindowBuilder::new(
        app,
        "deepseek-web",
        WebviewUrl::External(url),
    )
    .title("DeepSeek 网页")
    .inner_size(1200.0, 850.0)
    .resizable(true)
    .visible(true)
    .build()
    .map_err(|e| format!("创建 DeepSeek WebView 失败: {e}"))?;

    Ok(())
}
```


# 五、登录方案

第一次执行时：

```text
打开 DeepSeek WebView
        ↓
用户手动登录
        ↓
WebView 保存 Cookie
        ↓
以后自动复用登录状态
```

不需要保存：

- 用户名；
- 密码；
- Token；
- API Key；
- Chrome Profile；
- Cookie 文件。

登录信息由系统 WebView 自己保存。

## 登录检测

不能只通过 URL 判断登录状态，因为网页可能异步加载。

建议综合判断：

1. URL 是否包含登录路径；
2. 页面是否存在登录按钮；
3. 页面是否存在 DeepSeek 输入框；
4. 页面是否存在用户菜单；
5. 页面是否显示验证码或登录提示。

可以先实现基础版本：

```rust name=src-tauri/src/page_script.rs
pub const CHECK_LOGIN_SCRIPT: &str = r#"
(() => {
    const url = location.href.toLowerCase();

    const loginKeywords = [
        '/login',
        '/sign_in',
        'signin',
        'sign-in'
    ];

    const isLoginUrl = loginKeywords.some(item => url.includes(item));

    const bodyText = document.body?.innerText || '';

    const hasLoginText =
        bodyText.includes('登录') ||
        bodyText.toLowerCase().includes('sign in') ||
        bodyText.toLowerCase().includes('log in');

    const input = document.querySelector(
        'textarea[placeholder], #chat-input, [contenteditable="true"]'
    );

    return JSON.stringify({
        loggedIn: !isLoginUrl && !!input && !hasLoginText,
        url: location.href,
        hasInput: !!input
    });
})()
"#;
```

# 六、提示词执行流程

一次任务建议严格按照以下流程执行：

```text
1. 确保 DeepSeek WebView 存在
2. 等待页面加载完成
3. 检查用户是否登录
4. 如果 new_chat=true，则创建新对话
5. 找到输入框
6. 写入提示词
7. 点击发送或模拟 Enter
8. 记录发送后的页面状态
9. 轮询最后一条 AI 回复
10. 判断回复是否生成完成
11. 提取最终结果
12. 返回给 Vue
```

重点是：

> 不要只检测“页面上有没有文本”，因为旧对话中可能已经存在很多文本。

应该在发送前记录当前回复数量或内容，在发送后只关注新增的最后一条回复。

## 填充提示词并提交

```rust name=src-tauri/src/page_script.rs
pub fn build_submit_script(prompt: &str) -> Result<String, String> {
    let prompt_json = serde_json::to_string(prompt)
        .map_err(|e| format!("提示词序列化失败: {e}"))?;

    Ok(format!(
        r#"
        (() => {{
            const prompt = {prompt_json};

            const selectors = [
                'textarea[placeholder]',
                '#chat-input',
                'textarea',
                '[contenteditable="true"]'
            ];

            let input = null;

            for (const selector of selectors) {{
                const elements = document.querySelectorAll(selector);

                for (const element of elements) {{
                    const style = window.getComputedStyle(element);
                    const visible =
                        element.offsetParent !== null &&
                        style.visibility !== 'hidden' &&
                        style.display !== 'none';

                    if (visible) {{
                        input = element;
                        break;
                    }}
                }}

                if (input) break;
            }}

            if (!input) {{
                return JSON.stringify({{
                    success: false,
                    error: 'INPUT_NOT_FOUND',
                    message: '没有找到提示词输入框'
                }});
            }}

            input.focus();

            if (input instanceof HTMLTextAreaElement) {{
                const setter = Object.getOwnPropertyDescriptor(
                    HTMLTextAreaElement.prototype,
                    'value'
                )?.set;

                if (setter) {{
                    setter.call(input, prompt);
                }} else {{
                    input.value = prompt;
                }}
            }} else {{
                input.textContent = prompt;
            }}

            input.dispatchEvent(new InputEvent('input', {{
                bubbles: true,
                inputType: 'insertText',
                data: prompt
            }}));

            input.dispatchEvent(new Event('change', {{
                bubbles: true
            }}));

            input.dispatchEvent(new KeyboardEvent('keydown', {{
                key: 'Enter',
                code: 'Enter',
                keyCode: 13,
                which: 13,
                bubbles: true
            }}));

            input.dispatchEvent(new KeyboardEvent('keyup', {{
                key: 'Enter',
                code: 'Enter',
                keyCode: 13,
                which: 13,
                bubbles: true
            }}));

            return JSON.stringify({{
                success: true
            }});
        }})()
        "#,
        prompt_json = prompt_json
    ))
}
```

注意：

不同网页框架对受控输入框的处理方式不同。如果直接设置 `textarea.value` 无效，可以采用：

1. 聚焦输入框；
2. 使用页面原生 setter；
3. 派发 `input` 事件；
4. 派发 `change` 事件；
5. 最后模拟 Enter；
6. 如果 Enter 失败，再查找发送按钮并点击。

# 九、识别最新回复

当前仓库的 `chat.js` 已经有以下策略：

```javascript
.ds-markdown
[class*="markdown"]
[data-role="assistant"]
[class*="message-content"]
```

可以继续保留，但需要增加“发送前快照”。

## 发送前获取快照

```rust name=src-tauri/src/page_script.rs
pub const CAPTURE_BEFORE_SCRIPT: &str = r#"
(() => {
    const selectors = [
        '.ds-markdown',
        '[class*="markdown"]',
        '[data-role="assistant"]',
        '[class*="message-content"]'
    ];

    let count = 0;
    let lastText = '';

    for (const selector of selectors) {
        const elements = document.querySelectorAll(selector);

        if (elements.length > count) {
            count = elements.length;
            lastText =
                elements[elements.length - 1].innerText?.trim() || '';
        }
    }

    return JSON.stringify({
        count,
        lastText
    });
})()
"#;
```

发送后：

```rust name=src-tauri/src/page_script.rs
pub const READ_REPLY_SCRIPT: &str = r#"
(() => {
    const selectors = [
        '.ds-markdown',
        '[class*="markdown"]',
        '[data-role="assistant"]',
        '[class*="message-content"]'
    ];

    let candidates = [];

    for (const selector of selectors) {
        const elements = document.querySelectorAll(selector);

        for (const element of elements) {
            const text = element.innerText?.trim();

            if (text && text.length > 0) {
                candidates.push({
                    text,
                    element
                });
            }
        }
    }

    if (candidates.length === 0) {
        return JSON.stringify({
            text: '',
            generating: false
        });
    }

    const last = candidates[candidates.length - 1];

    const stopSelectors = [
        'button[aria-label*="stop"]',
        'button[aria-label*="Stop"]',
        'button[aria-label*="停止"]',
        'button[title*="stop"]',
        'button[title*="Stop"]',
        'button[title*="停止"]'
    ];

    let generating = false;

    for (const selector of stopSelectors) {
        const stopButton = document.querySelector(selector);

        if (
            stopButton &&
            stopButton.offsetParent !== null
        ) {
            generating = true;
            break;
        }
    }

    return JSON.stringify({
        text: last.text,
        generating
    });
})()
"#;
```

# 十、生成完成判断

DeepSeek 回复是流式生成的，不能在第一次读取到文本时立即返回。

推荐判断条件：

```text
回复文本非空
+
停止生成按钮不存在
+
连续两次读取文本完全相同
```

## 状态结构

```rust name=src-tauri/src/models.rs
use serde::Deserialize;

#[derive(Debug, Deserialize)]
pub struct PageReplyState {
    pub text: String,
    pub generating: bool,
}
```

## Rust 轮询

```rust name=src-tauri/src/deepseek.rs
use std::time::{Duration, Instant};
use tauri::WebviewWindow;

use crate::models::PageReplyState;
use crate::page_script::READ_REPLY_SCRIPT;

pub async fn wait_for_result(
    window: &WebviewWindow,
    timeout_ms: u64,
) -> Result<String, String> {
    let start = Instant::now();

    let mut previous_text = String::new();
    let mut stable_count = 0;

    loop {
        if start.elapsed().as_millis() >= timeout_ms as u128 {
            return Err("TIMEOUT".to_string());
        }

        let raw_state = window
            .eval(READ_REPLY_SCRIPT)
            .map_err(|e| format!("读取 DeepSeek 页面失败: {e}"))?;

        let _ = raw_state;

        /*
         * 注意：
         * Tauri 的 eval 主要用于执行脚本，实际项目中需要通过页面桥接
         * 将 JSON 结果回传给 Rust，不能简单依赖 eval 的返回值。
         */

        if !previous_text.is_empty() && stable_count >= 2 {
            return Ok(previous_text);
        }

        tokio::time::sleep(Duration::from_millis(1000)).await;
    }
}
```

上面的代码表达了轮询逻辑，但实际项目必须解决一个关键问题：

> 如何将注入 JavaScript 的执行结果返回给 Rust。

这也是纯 Tauri WebView 方案中最需要设计的部分。

# 十一、JavaScript 与 Rust 的通信方式

推荐采用：

```text
网页 JavaScript
  ↓
Tauri command
  ↓
Rust
  ↓
Tauri event
  ↓
Vue
```

但远程网页默认不应该拥有 Tauri IPC 权限，否则任意网页都可能调用本地 Rust 命令。

因此必须：

1. 只允许 `https://chat.deepseek.com`；
2. 只开放必要的 Command；
3. 不开放文件系统、Shell 等高权限；
4. 不让 DeepSeek 页面调用任意本地能力；
5. 对回传的数据做校验。

## 网页端回传页面状态

注入的脚本可以调用一个专用命令：

```javascript
window.__TAURI_INTERNALS__.invoke(
    'receive_deepseek_page_state',
    {
        state: JSON.stringify({
            text: replyText,
            generating: generating
        })
    }
);
```

Rust 接收：

```rust name=src-tauri/src/commands.rs
use serde::Deserialize;
use tauri::{AppHandle, Emitter};

use crate::models::PageReplyState;

#[derive(Debug, Deserialize)]
pub struct PageStatePayload {
    pub state: String,
}

#[tauri::command]
pub fn receive_deepseek_page_state(
    app: AppHandle,
    payload: PageStatePayload,
) -> Result<(), String> {
    let state: PageReplyState = serde_json::from_str(&payload.state)
        .map_err(|e| format!("页面状态解析失败: {e}"))?;

    app.emit("deepseek-page-state", state)
        .map_err(|e| format!("发送页面状态事件失败: {e}"))?;

    Ok(())
}
```

不过这个 Command 只能接收来自已配置的 DeepSeek 远程页面。

# 十二、建议使用一次性任务脚本

不要每秒重复向页面注入大型脚本。更好的做法是：

1. Rust 注入一次任务脚本；
2. 脚本自己监听 DOM；
3. 脚本发现结果完成后回传 Rust；
4. Rust 收到结果后结束任务。

## 页面任务脚本

```javascript name=src-tauri/scripts/task_runner.js
(() => {
    const taskId = '__TASK_ID__';
    const prompt = __PROMPT_JSON__;

    const inputSelectors = [
        'textarea[placeholder]',
        '#chat-input',
        'textarea',
        '[contenteditable="true"]'
    ];

    const replySelectors = [
        '.ds-markdown',
        '[class*="markdown"]',
        '[data-role="assistant"]',
        '[class*="message-content"]'
    ];

    function sendToRust(type, payload) {
        if (
            window.__TAURI_INTERNALS__ &&
            window.__TAURI_INTERNALS__.invoke
        ) {
            window.__TAURI_INTERNALS__.invoke(
                'receive_deepseek_page_event',
                {
                    event: JSON.stringify({
                        taskId,
                        type,
                        ...payload
                    })
                }
            );
        }
    }

    function findInput() {
        for (const selector of inputSelectors) {
            const elements = document.querySelectorAll(selector);

            for (const element of elements) {
                if (
                    element.offsetParent !== null &&
                    !element.disabled
                ) {
                    return element;
                }
            }
        }

        return null;
    }

    function getLastReply() {
        let lastText = '';

        for (const selector of replySelectors) {
            const elements = document.querySelectorAll(selector);

            for (const element of elements) {
                const text = element.innerText?.trim() || '';

                if (text.length > lastText.length) {
                    lastText = text;
                }
            }
        }

        return lastText;
    }

    function isGenerating() {
        const selectors = [
            'button[aria-label*="stop"]',
            'button[aria-label*="Stop"]',
            'button[aria-label*="停止"]',
            'button[title*="stop"]',
            'button[title*="Stop"]',
            'button[title*="停止"]'
        ];

        return selectors.some((selector) => {
            const element = document.querySelector(selector);

            return element && element.offsetParent !== null;
        });
    }

    function submit() {
        const input = findInput();

        if (!input) {
            sendToRust('error', {
                error: 'INPUT_NOT_FOUND',
                message: '没有找到 DeepSeek 输入框'
            });

            return false;
        }

        input.focus();

        if (input instanceof HTMLTextAreaElement) {
            const setter = Object.getOwnPropertyDescriptor(
                HTMLTextAreaElement.prototype,
                'value'
            )?.set;

            setter?.call(input, prompt);
        } else {
            input.textContent = prompt;
        }

        input.dispatchEvent(new InputEvent('input', {
            bubbles: true,
            inputType: 'insertText',
            data: prompt
        }));

        input.dispatchEvent(new Event('change', {
            bubbles: true
        }));

        const sendButton = document.querySelector(
            'button[type="submit"],' +
            'button[aria-label*="发送"],' +
            'button[aria-label*="send"],' +
            '[class*="send-button"]'
        );

        if (
            sendButton &&
            sendButton.offsetParent !== null &&
            !sendButton.disabled
        ) {
            sendButton.click();
        } else {
            input.dispatchEvent(new KeyboardEvent('keydown', {
                key: 'Enter',
                code: 'Enter',
                keyCode: 13,
                which: 13,
                bubbles: true
            }));
        }

        sendToRust('submitted', {});

        return true;
    }

    let previousText = '';
    let stableCount = 0;
    let hasText = false;

    const observer = new MutationObserver(() => {
        const text = getLastReply();
        const generating = isGenerating();

        if (text) {
            hasText = true;
        }

        if (text && text === previousText) {
            stableCount += 1;
        } else {
            stableCount = 0;
            previousText = text;
        }

        sendToRust('progress', {
            text,
            generating,
            stableCount
        });

        if (
            hasText &&
            !generating &&
            stableCount >= 2
        ) {
            observer.disconnect();

            sendToRust('completed', {
                result: text
            });
        }
    });

    observer.observe(document.documentElement, {
        subtree: true,
        childList: true,
        characterData: true
    });

    if (!submit()) {
        observer.disconnect();
    }
})();
```

这个方案比 Rust 每秒执行一次 `eval` 更稳定，因为网页自身可以实时监听 DOM 变化。

# 十三、Rust 接收任务事件

```rust name=src-tauri/src/commands.rs
use serde::Deserialize;
use tauri::{AppHandle, Emitter};

#[derive(Debug, Deserialize)]
pub struct PageEventPayload {
    pub event: String,
}

#[derive(Debug, Deserialize)]
struct PageEvent {
    #[serde(rename = "taskId")]
    task_id: String,

    #[serde(rename = "type")]
    event_type: String,

    text: Option<String>,

    result: Option<String>,

    generating: Option<bool>,

    error: Option<String>,

    message: Option<String>,
}

#[tauri::command]
pub fn receive_deepseek_page_event(
    app: AppHandle,
    payload: PageEventPayload,
) -> Result<(), String> {
    let event: PageEvent = serde_json::from_str(&payload.event)
        .map_err(|e| format!("DeepSeek 页面事件解析失败: {e}"))?;

    match event.event_type.as_str() {
        "submitted" => {
            app.emit("deepseek-task-submitted", &event)
                .map_err(|e| e.to_string())?;
        }

        "progress" => {
            app.emit("deepseek-task-progress", &event)
                .map_err(|e| e.to_string())?;
        }

        "completed" => {
            app.emit("deepseek-task-completed", &event)
                .map_err(|e| e.to_string())?;
        }

        "error" => {
            app.emit("deepseek-task-error", &event)
                .map_err(|e| e.to_string())?;
        }

        _ => {}
    }

    Ok(())
}
```

实际项目中建议：

- Rust 中维护 `task_id -> oneshot sender`；
- 收到 `completed` 时唤醒对应任务；
- 收到 `error` 时结束任务；
- 超时后取消任务；
- 同一时间只允许执行一个任务。

# 十四、Rust 执行任务 Command

```rust name=src-tauri/src/commands.rs
use std::time::Instant;
use tauri::{AppHandle, Manager};

use crate::models::{
    ExecuteTaskRequest,
    ExecuteTaskResponse,
    TaskStatus,
};

#[tauri::command]
pub async fn execute_deepseek_task(
    app: AppHandle,
    request: ExecuteTaskRequest,
) -> Result<ExecuteTaskResponse, String> {
    let started_at = Instant::now();

    if request.prompt.trim().is_empty() {
        return Ok(ExecuteTaskResponse {
            success: false,
            prompt: request.prompt,
            result: None,
            error: Some("MISSING_PROMPT".to_string()),
            message: Some("提示词不能为空".to_string()),
            elapsed_ms: 0,
            status: TaskStatus::Failed,
        });
    }

    let window = app
        .get_webview_window("deepseek-web")
        .ok_or_else(|| "请先打开 DeepSeek 网页".to_string())?;

    let _ = window;

    /*
     * 这里执行：
     *
     * 1. 检查页面状态
     * 2. 检查是否登录
     * 3. 创建新对话
     * 4. 生成任务 ID
     * 5. 注入 task_runner.js
     * 6. 等待 deepseek-task-completed 事件
     * 7. 验证事件 taskId
     * 8. 返回最终结果
     */

    Ok(ExecuteTaskResponse {
        success: true,
        prompt: request.prompt,
        result: Some("这里返回 DeepSeek 最终结果".to_string()),
        error: None,
        message: None,
        elapsed_ms: started_at.elapsed().as_millis() as u64,
        status: TaskStatus::Completed,
    })
}
```

生产实现时不要直接固定返回结果，需要连接事件通道。

```vue name=src/components/PromptForm.vue
import { ref } from 'vue'
import { invoke } from '@tauri-apps/api/core'

const prompt = ref('')
const result = ref('')

  if (!prompt.value.trim() || loading.value) {
    return
  }

  result.value = ''
  errorMessage.value = ''
  status.value = 'PREPARING'

      result?: string
      message?: string
      error?: string
      status: string

    if (response.success) {
      result.value = response.result || ''
    } else {
      errorMessage.value =
        response.message ||
        response.error ||
        'DeepSeek 任务执行失败'
    }
  } catch (error) {
    status.value = 'FAILED'
    errorMessage.value = String(error)
  } finally {
    loading.value = false
  }
}

      >

      </button>
```

# 十九、Tauri 权限配置

最重要的安全点是：

> 不能让任意远程网页获得 Tauri 的全部 IPC 权限。

只允许：

```text
https://chat.deepseek.com
```

调用一个专门的结果回传命令：

```text
receive_deepseek_page_event
```

不要让 DeepSeek 页面调用：

- 文件系统；
- Shell；
- 进程执行；
- 系统命令；
- 任意窗口控制；
- 任意 URL 打开；
- 数据库读写。

权限思路：

```json name=src-tauri/capabilities/default.json
{
  "identifier": "main-capability",
  "description": "DeepSeek task application capability",
  "windows": [
    "main"
  ],
  "permissions": [
    "core:default",
    "core:event:default",
    "core:window:default"
  ]
}
```

DeepSeek 页面窗口单独配置最小权限，只允许必要 IPC。

不同 Tauri 2.x 版本中，远程域名 IPC 配置字段可能略有区别，正式实现时应按照当前 Tauri 版本的 capability 配置格式设置。

核心原则是：

```text
只允许 chat.deepseek.com
只暴露 receive_deepseek_page_event
不授予远程网页文件和 Shell 权限
```

# 二十五、最终结论

最适合当前项目的方案是：

```text
Vue 3
  +
Tauri 2
  +
Rust
  +
Tauri WebView
  +
页面 JavaScript 自动化
```

具体实现：

```text
Vue 输入一段提示词
        ↓
Rust 创建或复用 DeepSeek WebView
        ↓
检查登录状态
        ↓
新建 DeepSeek 对话
        ↓
注入提示词
        ↓
点击发送
        ↓
监听 DeepSeek DOM 变化
        ↓
判断停止生成按钮消失
        ↓
判断回复文本连续稳定
        ↓
提取最后一条 AI 回复
        ↓
Rust 返回结果
        ↓
Vue 展示结果
```

不建议：

```text
Rust 直接请求 DeepSeek 内部接口
```

也不建议：

```text
Tauri 主窗口直接加载 DeepSeek 并混合业务 UI
```

更推荐：

```text
主窗口负责业务界面
DeepSeek 窗口负责网页执行
Rust 负责两个窗口之间的任务调度
```

这样最符合你的实际场景：**输入一段提示词，让 DeepSeek 网页执行，最终只获取结果，而不是实现一个传统聊天窗口。**
